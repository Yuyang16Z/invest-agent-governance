# AI 使用与验证记录

## 1. 用到的 AI 工具

| 工具 | 用在哪里 | 产出是否进入产品 |
|---|---|---|
| Claude Code（Claude Opus 5.5） | 阅读扶摇文档、设计数据模型与评测口径、编写全部代码与测试、调试误判、撰写文档、生成演示录屏脚本 | 代码与文档进入仓库；所有数字由脚本从数据重算，不来自 AI 手写 |
| DeepSeek `deepseek-flash` | ① 被测 Agent 的意图路由；② V1/V2/V3/V5 的回答生成；③ LLM 评审（相关性、个性化贴合） | 回答与评审原始输出入库，可追溯到 trace |
| DeepSeek `deepseek-v4-pro` | V4 候选版本的回答生成 | 同上 |

候选人做的决定与操作：选择用扶摇真实接口核验、用 DeepSeek 真实生成回答（而不是手写模拟回答）；自行签发并在本地 `.env` 写入两个 Key（AI 不接触 Key 的写入）；确认公开仓库 + GitHub Pages 发布与自动录屏方案。

## 2. AI 参与了哪些环节、怎么验证

| 环节 | AI 做了什么 | 验证方式 |
|---|---|---|
| 读题与接口调研 | 从扶摇 `llms-full.txt` 提取鉴权头、端点与字段 | 每个用到的端点都真实调用一次，核对字段名与单位（如季度利润表为累计口径：2026Q2 营收 2769 亿 > Q1 1291 亿） |
| 质量标准与指标 | 起草意图 × 维度的标准、22 项检查、指标口径、发布闸门 | 口径集中在 `standards.ts` / `metrics.ts`，网页直接渲染同一份配置；每个指标都能下钻到具体回答 |
| 被测 Agent | 编写路由、取数、上下文注入与 5 个版本配置 | 每条回答保存完整 trace（路由输出、工具调用、注入数据的 as_of、KYC 载荷、token） |
| 评测引擎 | 编写数字抽取、核验、合规、隐私、适当性、归因、统计检验 | 29 项单元测试；对 160 条真实回答逐条抽查“不符/命中”原文，误判逐个修正并补测试 |
| 前端 | 编写 7 个页面 | 本地与线上逐页打开，检查控制台无报错、数字与评测报告一致 |
| 文档 | README、测试说明、本记录 | README 与报告里的数字用 `npm run eval` 的输出逐项核对 |

## 3. 验证中发现并修正的错误或不合理结果

### 3.1 AI 生成代码的错误（平台误判）

| # | 现象 | 发现方式 | 修正 |
|---|---|---|---|
| 1 | V3 数值准确率只有 48.7%，与“数据已修复”的预期不符 | 列出全部“不符”项逐条读原文：几十个数字的标的都是 300033（同花顺） | 回答中的“来源：同花顺金融数据”被当成股票提及；改为先遮蔽数据来源短语 |
| 2 | “涨跌幅 +1.22%”被判为 -1.22 | 同上 | 方向词检测去掉“涨跌幅”这类中性词；显式正负号优先 |
| 3 | “跌1.5元”被当成涨跌幅 1.5% | 同上 | 单位兼容检查传错参数，改为原文单位 |
| 4 | Agent 的推算与举例（年化、差额、“例如回撤15%”）被判数字错误 | 同上 | 推算/举例/假设/区间语境记为“未识别”，不参与对错 |
| 5 | 画像一致性显示 V5 有三个画像“遗漏数字”，一度得出“亲和力 Prompt 导致选择性披露”的结论 | 打开对应回答，发现数字明明写了（“涨跌幅：-0.54%”） | 为跳过“15:00”而跳过了所有冒号后的数字。修正后 V5 画像不变性为 4/4，**原结论撤回**，README 按修正后的数据重写 |
| 6 | V5 的 10 个“数字错误” | 逐条读原文 | 全部是抽取问题（“近 5 日”带空格、“回调”未识别为下跌、“21世纪经济报道”里的 21）；修正后 V5 数值准确率 284/284 |
| 7 | 合规误报：“我不能给出‘买入/卖出/清仓’这类指令”“10月16日获融资买入2.17亿元” | 列出全部高危命中原文抽查 | 引号内为提及不计；杠杆规则要求出现建议动词；排除“金融资产”里的“融资” |
| 8 | 单测“约1300元 vs 1329”失败 | `npm test` | 测试预期写宽了（偏差 2.2% > 2% 容差）；改为一正一反两条用例明确容差边界，未放宽引擎 |

### 3.2 外部数据与模型调用的问题

| # | 现象 | 处理 |
|---|---|---|
| 9 | 扶摇返回 `code=2003 Invalid or revoked API key` | 不打印 Key，只检查 `.env` 该行的长度和前缀，发现首字符缺失；由候选人自行补全 |
| 10 | 基金最大回撤接口对 5 只基金都返回全 0 | 判为数据未就绪，改用复权净值推算并标注口径（见测试说明 3.1） |
| 11 | 基金区间收益接口 `timestamp=0`，没有数据时点 | 以最新净值日期标注 as_of，写入异常日志 |
| 12 | V4（deepseek-v4-pro）5 条回答为空，`finish_reason=length` | 思考过程用完了 3200 个输出 token；上限提到 8000 后只重跑这 5 条 |
| 13 | LLM 评审 21 条输出无法解析为 JSON | 同样是思考 token 用尽导致内容为空；上限提到 2500 后重跑，剩 1 条仍失败，保留为“评审调用失败” |

### 3.3 判断层面的修正

- **截止时间**：题面写“48 小时内”，笔试页面只显示“2026-10-18 06:56”且未注明时区。投递完成页的本地保存时间（10-15 17:56 CDT）正好对应北京时间 10-16 06:56 的开考时间，据此判断页面是北京时间，按本地 17:56 截止排期。
- **结论跟着数据走**：原设计预期 V5 会被闸门拦下；修正误判后实测 V5 通过，README 如实写“通过，但 P3 删除了适当性约束，需补红队样本”，没有为了故事保留错误结论。
- **不让 LLM 判数字**：评审 Prompt 明确“不评估数字对错”，数字只由确定性核验判断，避免 LLM 评审与数据核验重复、互相打架。

## 4. 仍需人工把关的地方

- 规则与评审都可能误判，所以高危命中、无法核验、评审分歧一律进入人工复核队列；本仓库没有附人工复核结果，复核页的记录只保存在使用者自己的浏览器里。
- 构造的产品风险等级、KYC 画像和模拟反馈只用于演示机制，不代表真实业务数据。
